# 桌面清理机器人抓空自恢复（ACT 策略 + 双证据视觉判别）

单台六自由度桌面机械臂在「语音下达整理指令 → 抓取 → 投入收纳区」这条链上，用**双证据视觉判别**识别抓空并自动重试的自建代码。判别、编排、指令层与前置自检均为本项目自行实现，策略训练与真机推理复用 LeRobot / LeLab 的 ACT 行为克隆。

配套记录见 ORecord 上的《基于多模态交互与双证据视觉判别的桌面清理机器人抓空自恢复研究》，本文只说明代码本身的组织方式与设计取舍。

---

## 一、这套代码是怎么想出来的

一条真机执行链最容易出问题的不是模型，而是「同一件事有两处定义」和「判定被执行的副作用污染」。下面八条是全部结构决定的来源。

**1. 只留一个生产入口。** `grasp_retry/run_trial.py` 独占取帧、判别、分支与落盘。其他脚本一律调用它而不另写门限——`judge_now.py` 与 `label_eval.py` 开头就是 `import run_trial`，复用同一套判据。改门限只有一处，不会出现「补判和主循环结论不一致」。

**2. 判别与执行物理分离。** 机械臂动作由 LeLab 的 `lerobot_rollout` 子进程经 8000 端口驱动，判别侧只做两件事：读推理日志里的三行事实（上下文构建、控制循环启动、执行结束）判断阶段，读相机帧判断结果。判别不参与控制，控制不参与判定。

**3. 从「数像素」改成「数实例」。** 早期判据是框内目标像素总量，实测会被两类噪声击穿：机械臂橙色外壳进入视野时黄区红像素从 26 涨到 10182；黄板被阴影压暗时灰像素从 200 涨到 5781。两者都会把失败判成成功。`blocks.py` 改为三路颜色掩码（红 / 灰 / 深色）取连通域，再用面积、边长、填充率三项形状约束过滤——外壳是长条、阴影是散斑，过不了方块形状，噪声实例数归零。

**4. 双证据才判成功。** 单看「原位变空」会把「推到桌子边上」判成搬走。判定要求原位占比低于 0.40 **且**收纳区增料达到半个单块当量，两条同时成立才记成功；只成立第一条记「丢失」。方块被推出原位而未入区就是这条规则的典型命中。

**5. 候选必须落在外接框内。** 蓝区与黄区的外接矩形之外一律不认，否则画面顶部的夹爪会被当成候选方块，把「原位」画在夹爪上，判定必然错。

**6. 早停要补判。** 人工中止时机械臂常已完成投放但没来得及判定。停稳后等 1.5 s 补拍一帧，用同一门限重判，把这类轮次从「未判定」救回「成功」，避免系统性低估成功率。

**7. 指令层不上大模型。** `intent.py` 是规则表：否定优先、急停优先、确认、整理类、只读类、无法识别，输出技能标识与离散参数，不生成关节轨迹。理由是同一句话两次解析必须得到同一技能，否则真机安全无从验证；规则表还能逐条被评审指着问。ASR 同音错字只做白名单字面映射，不开放模糊匹配。

**8. 真值不许脚本回填。** 逐轮结论由人工对录屏复核后填写，脚本只能汇总。机判自证会让指标失去意义，因此这一条写进流程而不是写在注释里。

另有两处工程坑是踩出来的，留在代码里当护栏：子进程必须带独立进程组启动，否则 `lerobot_rollout` 孙进程杀不掉；推理服务空闲标志读错字段名时，页面表现与「模型没加载」完全一致，`check_ready.py` 因此把「可执行模型同时存在于任务队列与本地检查点」单独列为一项。

## 三、环境

- Python 3.10+；Windows（批处理入口、串口、tkinter 标定界面均依赖 Windows）。
- LeRobot / LeLab 已装好并能启动推理服务（默认 `http://127.0.0.1:8000`）。
- 相机两路：环境相机用于判定（默认 index 0），腕部相机随臂移动，由 LeLab 侧配置。
- LeLab 的 venv 解释器用环境变量 `LELAB_PY` 指过去；不设则退回 `PATH` 上的 `python`。仓库内不含任何本机绝对路径。

```bat
set "LELAB_PY=<安装 LeRobot 的 venv 里 python.exe 的完整路径>"
pip install -r requirements.txt
copy agent\config.example.json agent\config.json
```

`faster-whisper` 未安装时指令层自动降级为纯文字输入，链路其余部分不变。

## 四、跑起来

**第 0 步 标定**（首次或相机/收纳区移位后必须重做）

```bat
cd grasp_retry
calibrate_bin.bat
```

结果写入 `bin_roi.json`，再打开 `bin_roi_preview.png` 人工核对边界是否贴合板面。未标定时 `run_trial.bat` 拒绝启动。

**第 1—2 步 前置自检**

```bat
check_arm.bat
check_ready.bat
```

`check_ready.bat` 六项全绿才可继续。它同时核对可执行模型在任务队列与本地检查点两侧都在，防止策略引用指向旧模型——那种故障的表现只是「连续抓空」，不会报错。

**第 3 步 视觉基准**

```bat
python _cam_check.py
```

输出标注图 `check_out/cam_check.png`。

**第 4 步 单次执行与判别**

```bat
run_trial.bat
```

手动模式由人在 LeLab 点推理按钮，脚本负责取帧、判别与记录；自动模式追加 `--policy-ref <ACT 检查点目录>`。判成功即停、判抓空即重试、判丢失即终止、连续抓空超过两次转人工，轮次预算三次。

**第 5 步 指令链路（单次演示）**

```bat
cd ..\agent
start_agent.bat
```

自动打开 `http://localhost:8100`：点语音或直接输入「清理桌面」→ 核对转写 → 确认（30 s 内有效）→ 机械臂执行 → 结果回传。急停随时可用。演示录制用 `demo_once.bat`，写独立目录，不与正式试验混合。

**第 6 步 汇总**

`run_trial.py` 的 `--export-review` / `--confusion` 输出逐轮结论与混淆矩阵，供人工填真值后计算指标。

## 五、门限与出处

| 参数 | 默认 | 含义 |
| --- | --- | --- |
| `--keep-ratio` | 0.40 | 原位占比低于此值才认「原位变空」 |
| `BIN_GAIN_UNIT` | 0.5 | 收纳区增料达到半个单块当量才认「已入区」 |
| `--min-area` | 600 | 连通域面积下限 |
| `--dark-v` | 100 | 深色门限，V ≤ 此值即认作方块（不受黄板浸染影响） |
| `--gray` | 30,170,100 | 低饱和灰掩码 |
| `--hsv` | 关闭 | 红色路，仅在旧红块数据集上手动开启 |
| `MAX_EMPTY_STREAK` | 2 | 连续抓空上限，超过即放弃转人工 |
| `--max-attempts` | 3 | 单次试验轮次预算 |
| `duration` | 280 | 单轮执行时长（秒） |

形状参数（面积、边长、填充率）由 `fit_blocks.py` 在训练集全部 36 集上网格搜索得到，并以偶数集定参、奇数集复测做留出验证，三项指标在两组子集上一致，非过拟合。

> 红色路默认关闭的原因：当前布局的目标是灰方块，桌上那颗红色圆柱是**固定干扰物**。开启红色路会让它进入候选，一旦被选中，「原位」就画在干扰物上，判定必然错。

## 六、边界与已知限制

- **`bin_roi.json` 是原始机位的标定结果**，含边界框与阈值口径，用作参考；换桌面、换相机高度必须重新标定。
- **不含权重与数据**：ACT 检查点、`faster-whisper-small`、检测权重、数据集与录屏均不入库，按记录中的链接获取。
- **分组参数为历史对照保留**：`--group A/B/MIX` 与 `NONINFERIORITY_MARGIN` 是 A/B 对照阶段的实现，正式记录按单组口径展开（等价于判别器驱动的 B 分支），A 组分支仅作历史可复现性保留。
- **不生成轨迹**：`intent.py` 只输出技能与离散参数，关节轨迹由策略网络产生，改指令层不影响动作空间。
